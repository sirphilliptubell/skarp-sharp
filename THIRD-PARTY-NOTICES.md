## What is shipped

| Package | Content | Third-party code inside |
|---|---|---|
| `Skarp` | pointer package, no binaries | none |
| `Skarp.win-x64`, `Skarp.linux-x64` | Native AOT executable `skarp` / `skarp.exe` | Roslyn (Microsoft.CodeAnalysis), CliWrap, the MCP C# SDK (ModelContextProtocol.Core) with three Microsoft.Extensions abstractions packages, and the .NET runtime and base class library compiled into the executable |
| `Skarp.any` | framework-dependent IL: `skarp.dll`, `SkarpSharp.Core.dll`, `CliWrap.dll`, `Microsoft.CodeAnalysis.dll`, `Microsoft.CodeAnalysis.CSharp.dll`, Roslyn's localized resource assemblies, `ModelContextProtocol.Core.dll`, `Microsoft.Extensions.AI.Abstractions.dll`, `Microsoft.Extensions.Logging.Abstractions.dll`, `Microsoft.Extensions.DependencyInjection.Abstractions.dll` | Roslyn, CliWrap, the MCP C# SDK and the three abstractions packages; the .NET runtime is not included (the user installs it) |

`SkarpSharp.Core` is the library project that holds the analysis logic. It is compiled into every package above; its csproj sets `IsPackable` to false, and no separate `SkarpSharp.Core` package is published (if one is published later, it carries Roslyn, CliWrap and ModelContextProtocol.Core as NuGet dependencies, and this file applies to it unchanged).

The set was determined from the build: `dotnet list package --include-transitive` on `src/SkarpSharp.Cli` and `src/SkarpSharp.Core`, the contents of the packed `Skarp.any` package, the compiler and linker inputs of the win-x64 Native AOT build (`skarp.ilc.rsp`, `link.rsp`), and the NativeAOT and runtime packs the SDK restored for `win-x64` and `linux-x64` (see the end of this file for what was checked and not redistributed).

Source: https://github.com/dotnet/roslyn (package repository commit 1324e1d34a0490454837a22370e75bbaeecffb87). ### .NET runtime and base class library (10.0.15)

In the Native AOT packages the runtime (garbage collector, type loader, native runtime libraries) and the used parts of the base class library are compiled and linked into the `skarp` executable. License text: `LICENSE.TXT` of the Microsoft.NETCore.App.Runtime.NativeAOT.win-x64 10.0.15 package (identical to the MIT text for Roslyn above). The same package carries `THIRD-PARTY-NOTICES.TXT`, reproduced in full in the appendix, because the runtime embeds code under other licenses (for example zlib-ng, Brotli, and others listed there). The `linux-x64` package uses Microsoft.NETCore.App.Runtime.NativeAOT.linux-x64 10.0.15, whose `LICENSE.TXT` and `THIRD-PARTY-NOTICES.TXT` differ from the win-x64 ones only in line endings (LF instead of CRLF), so the texts here cover both executables. The 10.0.15 packs carry the same `LICENSE.TXT` and `THIRD-PARTY-NOTICES.TXT` as the 10.0.12 packs (compared byte for byte, apart from the line endings of the Linux files), so the texts did not change when the build moved to 10.0.15. Not every item in that file ends up in the executable; the file is included whole rather than guessing which parts do.

## Checked and not redistributed

These appear in the build but their code is not in the shipped output (the `Skarp.any` package contents were inspected; the Native AOT executable links the NativeAOT runtime pack named above plus the platform toolchain parts described in the last two items).

- Microsoft.DotNet.ILCompiler 10.0.15 and runtime.win-x64.Microsoft.DotNet.ILCompiler / runtime.linux-x64.Microsoft.DotNet.ILCompiler 10.0.15: the Native AOT compiler toolchain, used at build time only.
- Microsoft.NETCore.App.Runtime.win-x64 / .linux-x64, Microsoft.NETCore.App.Host.linux-x64 and Microsoft.AspNetCore.App.Runtime.* 10.0.15: restored by the SDK for the runtime identifier, but the Native AOT compiler references only the NativeAOT runtime pack (checked in `skarp.ilc.rsp`), and the `any` package does not bundle the runtime.
- Microsoft.NET.ILLink.Tasks 10.0.15: trimming tools, build time only.
- Microsoft.CodeAnalysis.Analyzers 5.9.0: transitive analyzer package of Roslyn, analyzers run during our build and are not copied into any package.
- MinVer 8.0.0 (MIT): build-time package that sets the version from the Git tag (PrivateAssets, not copied into any package).
- Test project dependencies under `tests/` (test frameworks and similar): used only to run tests.
- The Windows C/C++ toolchain (MSVC linker and libraries) used to link the Windows executable. Part of it does end up in `skarp.exe`: the runtime's static libraries carry `/DEFAULTLIB` directives for `libcmt` and `libcpmt` (the static MSVC C runtime with vcruntime, and the static C++ library), and `skarp.exe` imports no `VCRUNTIME140.dll`, so that startup and support code is linked statically. The Universal C Runtime is linked dynamically (`/NODEFAULTLIB:libucrt.lib /DEFAULTLIB:ucrt.lib` in the ILCompiler Windows targets; the executable imports `api-ms-win-crt-*`), and it is part of Windows. The static MSVC libraries come under the Visual Studio license terms of the build machine, not an open-source license, and are not listed above; check those terms before release.
- On Linux, the executable links dynamically against the system C library and links the GCC/Clang startup objects of the build machine; these are toolchain parts, not redistributed components with notice requirements in this file (not verified on a Linux build here).
