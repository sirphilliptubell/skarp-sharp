serverInfo: skarp
instructions (1101 characters):
Skarp measures C# code health with Roslyn. Each file gets a score from 1 to 10, where 10 is healthy, lowered by its findings: places worth a look such as complex, long or deeply nested methods, large types, long parameter lists and duplicated code (with a solution also class coupling, god classes and unused code).
find_worst_code ranks the least healthy files or methods under a folder, worst first: use it to find what to clean up or review first.
check says what the changed C# files made worse or better, against the baseline or else the last commit. Call it on the C# files you edited before you finish a task. Where Skarp notes already appear after each edit, they cover that edit; check then covers changes made another way.
findings lists the findings of the saved run, or shows one in full by its id with how to improve it.
explain describes a rule: what it measures, why it matters, how to improve code it flags and the thresholds in force.
Bands: 9 or more is healthy, 4 to below 9 problematic, below 4 unhealthy. A healthy file is not worth reworking just because it appears in a ranking.
